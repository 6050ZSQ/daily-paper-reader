## 摘要
语言特定能力（LSC）是指语言模型根据提示语言的不同而表现更好或更差的现象。换句话说，当用不同语言提示相同语义查询时，语言模型会输出不同（且可能不正确）的响应。先前的工作将其归因于跨语言语义表示的内部不对齐。目前，文献中主要有两种方法来解决LSC：（1）将所有查询路由到英语，提高性能，但将语言表达限制在英语；（2）在语言平衡数据上进行训练，均衡模型跨语言的性能，但降低整体性能。在这项工作中，我们采取数据中心的视角，并引入HOTFIXR：用于改进跨语言推理的硬度优化训练数据。这是一个数据生成框架，使用模型来探查和学习学生模型的多语言弱点，并生成数据以缓解这些弱点。HOTFIXR可以生成多语言合成训练数据，以提高多语言性能。我们在三个分布内任务、三个分布外任务和四种分布外语言上进行了评估。平均而言，HOTFIXR（1）将分布内性能提高了6.2%，（2）在分布外任务上将（由微调引起的）灾难性遗忘减少了3.7%，（3）在分布外语言上减少了7.1%。总的来说，由于许多现实世界应用需要多语言LLM，我们的工作致力于使LLM具备多语言能力。代码将在接受后发布。

## Abstract
Language-specific competency (LSC) is the phenomenon of a language model performing better or worse depending on the language of the prompt. In other words, a language model outputs different (and potentially incorrect) responses to the same semantic query when prompted in different languages. Prior work attributes this to an internal misalignment of semantic representation across languages. Currently, there are two main approaches to address LSC in the literature: (1) routing all queries through English, improving performance, but limiting language expressivity to English; or (2) training on language-balanced data, equalizing model performance across languages, but reducing overall performance. In this work, we take a data centric perspective and introduce HOTFIXR: Hardness Optimized Training data For Improving X-Lingual Reasoning. It is a data generation framework that uses models to probe and learn a student model's multilingual weaknesses, and generates data to mitigate them. HOTFIXR can generate multilingual synthetic training data that can improve multilingual performance. We evaluate on three in-distribution tasks, three out-of-distribution tasks, and four out-of-distribution languages. On average, HOTFIXR (1) improves in-distribution performance by 6.2%, (2) reduces catastrophic forgetting (induced by fine-tuning) on OOD tasks by 3.7%, and (3) on OOD languages by 7.1%. Overall, as many real-world applications requires multilingual LLMs, our work contributes to the efforts of making LLMs multilingually proficient. We will release code upon acceptance.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：多语言大模型（LLM）存在“语言特定能力”（Language-Specific Competency, LSC）问题——即对同一语义查询，当使用不同语言提问时，模型可能给出不同甚至错误的回答。这种现象源于模型在不同语言之间内部语义表示的不对齐（representation misalignment）。
- **根因**：预训练数据中英语占比过高，导致模型在处理非英语时倾向于将理解锚定到英语空间（“英语思维”），英语成为非英语理解能力的上限。即使模型在较均衡的多语言数据上训练（如Aya-23），虽能提升跨语言一致性，却以牺牲英语/整体性能为代价——即“多语言诅咒”。
- **现有方案的局限**：
  - 将所有查询路由到英语：提升性能，但丧失语言表达性；
  - 在语言均衡数据上训练：拉平跨语言差异，但降低整体准确率。
- **本文目标**：寻找中间路线——通过**数据中心的训练后数据生成**，在不显著损失整体能力的前提下，提高模型的多语言能力。为此提出 **HOTFIXR（Hardness Optimized Training-data For Improving X-lingual Reasoning）**。

## 2. 方法论

### 2.1 核心思想
- 训练一个**问题生成模型**，使其依据**学生模型自身的弱点反馈**来生成针对性训练数据。
- 生成过程被形式化为一个“数据空间登山”问题：在数据空间中搜索能够最大化“语言缺陷分数（Lingual Deficit Score）”的样本。
- 优化算法使用 **GRPO**（Group Relative Policy Optimization）。

### 2.2 语言缺陷分数（Lingual Deficit）
由两部分组成，取二者与1的较小值之和：

- **语言无关能力不足（LAI）**：
  - 用英语提示学生模型回答问题；
  - 使用模型回答序列中每个位置最高概率 token 概率的均值计算不确定性：  
    \( U(P,R) = 1 - \frac{1}{|R|}\sum_t p_\theta(R^{(1)}_t | P, R_{<t}) \)
  - 不确定性越高，奖励越大。

- **语言特定能力不足（LSI）**：
  - 分别用英语和某种目标语言（如法语、西班牙语等）提示模型进行推理；
  - 取两种推理轨迹最后一个推理 token 的最后一层隐藏状态，计算**余弦距离**；
  - 距离越大，说明跨语言表示越不对齐，奖励越大。

- **直觉**：HOTFIXR 偏向生成那些模型“答不准”（LAI 高）或“不同语言推理路径分歧大”（LSI 高）的样本，从而针对性修补弱点。

### 2.3 训练流程
1. 用约 500 个种子样本（Nemotron PTDv2 的 STEM/MATH/CHAT 各 167 个）作为上下文，训练问题生成模型；
2. 通过 GRPO 优化问题生成器，使其产出高语言缺陷分数的样本；
3. 用训练好的生成器生成 5,000 个训练样本（语言涵盖英、法、西、阿、葡、意六种）；
4. 用 Qwen2.5-32B-Instruct 为样本生成标签；
5. 对目标学生模型做 SFT 微调并评估。

### 2.4 防止奖励黑客
- 训练样本小（500条）、GRPO 仅约 40 步，避免生成器陷入局部最优导致重复生成同一样本。

## 3. 实验设计

### 3.1 评估任务与数据集
- **分布内（ID）任务**：Nemotron STEM（准确性）、Nemotron MATH（LLM-as-Judge）、Nemotron CHAT（LLM-as-Judge）。
- **分布外（OOD）任务**：
  - 事实知识：MMMLU；
  - RAG阅读理解：多语言 HotPotQA；
  - 翻译：OPUS-100。
- **语言**：
  - ID 语言：英语、法语、西班牙语、阿拉伯语、葡萄牙语、意大利语；
  - OOD 语言：德语、日语（MMMLU/OPUS）；俄语、中文（mHotPotQA）。

### 3.2 模型
- 学生模型：Qwen2.5-7B-Instruct、Qwen2.5-14B-Instruct、Llama-3.1-8B-Instruct。
- 标签生成模型：Qwen2.5-32B-Instruct。
- 评估裁判：Prometheus-7b-V2.0。

### 3.3 对比基线
- **Base**：不训练；
- **EngReason**：训练-free，强制用英语推理；
- **SelectionGT**：从原始数据选择 5,000 条（真实标签）训练；
- **SelectionGEN**：数据选择 + 用 Qwen 32B 生成标签；
- **Filtered**：用语言缺陷分数从 10,000 条中筛选 TOP 5,000 条；
- **Untrained**：用未经训练的生成模型合成数据；
- **DataEnvGym**：现有数据合成基线，本文将其扩展为按语言生成。

### 3.4 评价指标
- 多项选择：准确率；
- 短答案：ROUGE-L（≥80% 判对）；
- 翻译/语义任务：LLM-as-Judge（≥4/5 判对）。

## 4. 资源与算力

- 论文明确提及：HOTFIXR 使用 **6 块 NVIDIA A100 GPU**，执行约 **40 步 RL 优化**，训练数据生成器的成本约为 **0.96 分钟/训练样本**，总计约 **8 GPU 小时**（针对 |D_QG|=500）。

## 6. 主要结论与发现

- HOTFIXR 在 **ID 任务上平均提升 6.2%**，且在 9/9 设置中优于 Base；
- 在 **OOD 任务上仅比 Base 下降 0.9%**，并显著优于其他训练型基线（平均改善 5.6%）；
- 在 **OOD 语言上**，相比其他方法平均减少 7.1% 的灾难性遗忘；
- 在多语言一致性（跨语言性能离散度）上，HOTFIXR 有轻微改善（如 CV 最低，0.11）；
- 消融显示：LAI 和 LSI 单独作用有限，但两者结合能有效提升生成数据质量；
- 持续学习中，第二轮 HOTFIXR 可进一步提升 7%（Nemotron）、8%（OOD 任务）和 8%（可见/不可见语言）。

## 7. 优点

- **数据中心视角**：不改变模型架构，直接优化训练数据，实用性强；
- **奖励设计新颖**：将“跨语言表示差距（LSI）”与“模型固有不确定性（LAI）”结合，能定位真实弱点；
- **小样本训练生成器**：只需 500 条种子数据即可，避免奖励黑客，控制成本；
- **泛化性验证全面**：覆盖多种模型、任务、语言、OOD 场景；
- **一次性成本**：生成器训练后可复用，适合真实业务场景；
- **对灾难性遗忘的缓解显著**，优于当前主流数据合成方法。

## 8. 不足与局限

- **语言覆盖有限**：仅聚焦高资源语言（英语、法语、西班牙语等），对低资源语言未做专门处理；
- **依赖强标签模型**：需要 Qwen2.5-32B 这样的大模型生成可靠标签，小模型自身生成标签质量不足，限制其自主闭环能力；
- **不可验证领域未知**：研究局限于有明确正确/错误答案的任务，能否推广到开放域/创造性任务未可知；
- **OOD 性能仍有下降**：相比 Base，HOTFIXR 在 OOD 任务上仍损失 0.9%，并未完全解决遗忘问题；
- **跨语言一致性提升有限**：论文承认在一致性指标上仅有轻微改善，并非显著的 SOTA；
- **潜在有害数据风险**：对于训练数据偏见严重的模型，合成数据可能引入有害内容，论文仅在可验证任务上做了规避。
- **未在预训练规模验证**：作者指出多语言表示主要形成于预训练阶段，但本文仅限于后训练微调，未来需在大规模预训练中验证可扩展性。
