## 摘要
大型语言模型越来越多地根据自然语言描述编写 TLA$^{+}$ 形式规范，但进展难以衡量：现有资源通过输出与参考的相似性或是否能通过解析来评分，这两者都不能证明正确性。我们提出了 TLA$^{+}$-Bench，一个通过执行来评分的数据集和基准。每个金标准规范都附带一个配置，TLA$^{+}$ 模型检查器在完整可达状态空间上运行该配置，精确判定该规范是否具有该配置所命名的属性。该数据集包含来自 13 个公共仓库的 403 个经过模型检查的金标准规范和 897 个仅解析的银标准规范，涵盖了先前 TLA$^{+}$ 生成数据，并包含来自两个提供方的两种风格的四个模型撰写的描述，附有难度和类别标签。我们的主要发现涉及衡量本身：一个精确的评判器给出的不是一个正确性数字，而是一个范围。仅改变先前基准未明确说明的评分选择，在一组固定的模型输出上，正确率变化了六倍，从 10.0% 降至 1.7%；增加接口提供选择（即模型被告知配置的名称）后，范围扩大到十一倍，从 18.7% 降至 1.7%。我们将这个范围称为正确性包络，并测量其每个边界。其内部发现是稳定的。每个模型写出有效 TLA$^{+}$ 的频率远高于写出正确 TLA$^{+}$ 的频率：最强的模型在默认情况下正确率为 16%，在给定接口名称时正确率为 26%，开放模型最多为 1%，正确率随难度急剧下降。

## Abstract
Large language models increasingly write TLA$^{+}$ formal specifications from natural-language descriptions, but progress is hard to measure: existing resources grade by resemblance to a reference or by whether the output parses, neither of which shows correctness. We present TLA$^{+}$-Bench, a dataset and benchmark that grades by execution. Every gold specification ships a configuration the TLA$^{+}$ model checker runs over the full reachable state space, deciding exactly whether the specification holds the properties that configuration names. The dataset holds 403 model-checked gold and 897 parse-only silver specifications from 13 public repositories, subsumes prior TLA$^{+}$ generation data, and carries four model-written descriptions in two styles from two providers, with difficulty and category labels. Our main finding is about measurement itself: an exact oracle gives not one correctness number but a range. Varying only the grading choices earlier benchmarks leave unstated, on one fixed set of model outputs, the correct rate moves sixfold, from 10.0\% to 1.7\%; adding the interface-supply choice, where the model is told the configuration's names, widens the range to elevenfold, from 18.7\% to 1.7\%. We call this range the correctness envelope and measure each of its bounds. The findings inside it are stable. Every model writes valid TLA$^{+}$ far more often than correct TLA$^{+}$: the strongest is correct 16\% of the time by default and 26\% when given the interface names, open models at most 1\%, and correctness falls sharply with difficulty.

# 论文总结：TLA⁺-Bench：面向自然语言到 TLA⁺ 规范生成的可执行基准与数据集

## 1. 核心问题与整体含义

- **研究背景**：大型语言模型（LLM）越来越多地被用于从自然语言描述编写 TLA⁺ 形式规范。TLA⁺ 是描述并发和分布式系统的规范语言，配有解析器（SANY）和模型检查器（TLC），可判定规范是否满足指定性质。
- **核心问题**：如何衡量 LLM 在此任务上的进展？现有资源要么按输出与参考规范的相似度评分，要么只检查输出是否能被解析，二者都无法反映规范是否真正正确。
- **整体含义**：作者提出 TLA⁺-Bench，用“执行”来评分——通过模型检查器遍历完整可达状态空间，精确判定生成的规范是否满足配置中声明的性质。结果发现，一个“精确的评判器”并不会给出单一的正确答案，而是会产生一个“正确性包络”（correctness envelope）：仅改变先前基准未明确说明的评分选择，正确率就会在六到十一倍的范围内波动。这提示评测设计本身对结论有巨大影响。

## 2. 方法论

- **数据集构建**：
  - 从 13 个公共仓库抓取 TLA⁺ 模块，经过去重和清洗后，保留 1,300 个规范。
  - 其中 403 个为 **gold**（可通过 SANY 解析，并附带能在 TLC 上运行通过的配置），897 个为 **silver**（仅能解析，无运行配置）。
  - 每个规范配有四种模型生成的描述（两种风格 × 两个提供方）：
    - **声明式（declarative）**：保留模块真实名称，描述系统做什么；
    - **意图式（intent）**：隐藏模块名称，只描述需求目标，要求模型自行设计接口。
  - 提供方为 GPT-5 和 Claude Opus 4.5；同时标注难度（基础/中级/高级）和类别（系统/工具等）。
- **评分流程**：
  - **有效性门**：生成输出必须先通过 SANY 解析；
  - **语义门**：将参考配置与输出一起运行 TLC，TLC 在完整可达状态空间上检查配置命名的属性是否被违反；无违反才计为“正确”。
  - 该方式是精确判定（相对于参考配置及有界常量），而非测试集上的近似估计。
- **正确性包络**：四种可辩护的评分规则：
  - *默认*：只给描述，要求模型自行恢复接口名称；
  - *配置感知*：额外提供常量名和属性名；
  - *实质性*：要求通过时确实发生了行为（多于一个状态）且检查的不是类型不变量或重言式；
  - *突变存活*：将检查的安全不变量替换为 TRUE 后重新运行，仍失败才算通过。
- **失败分类法**：包括解析失败、配置绑定失败、畸形时态公式、安全违规、活性违规、运行时错误、死锁、资源超限等八类。

## 3. 实验设计

- **基准评估集**：从 403 个 gold 规范中选取 **系统类别** 的 146 个，再剔除 46 个“平凡固定装置”（仅一个可达状态、任何模型都能通过的规范），最终得到 **100 个评估规范**，难度分布接近均匀（35 基础 / 34 中级 / 31 高级）。
- **评估模型**：
  - 前沿模型：GPT-5、Gemini-2.5-pro、Claude Opus 4.5；
  - 开放模型：qwen2.5-coder-32b、llama3.3-70b、gpt-oss-20b。
- **输入设置**：所有模型使用同一份由 GPT-5 撰写的声明式描述（每规范一个输出，共 600 个输出用于主结果）；配置感知模式额外生成一组新输出。
- **对比维度**：
  - 解析率 vs. 正确率（EQ1）；
  - 难度分层下的正确率（EQ2）；
  - 失败指纹与困难度关系（EQ2）；
  - 默认 vs. 配置感知模式；
  - 通过质量分析（实质性屏幕、突变测试，EQ3）。
- **与先前资源的对比**：论文将 TLA⁺-Bench 与 FormalLM、SysMoBench、HumanEval、DafnyBench、VERINA 等作了系统比较，强调 TLA⁺-Bench 同时具备精确 oracle、真实规范、自然语言驱动、双风格描述、难度分层、质量分层和公开释放等特征。

## 4. 资源与算力

- 论文中**没有明确给出** GPU 型号、数量、训练时长等算力信息。
- 仅提到：
  - 前沿模型使用托管端点（GPT-5、Claude Opus 4.5、Gemini-2.5-pro）；

- 因此，资源细节不足，但作者释放了全部模型输出，支持在可比硬件上复现。

## 5. 实验数量与充分性

- **实验数量**：
  - 主实验：6 个模型 × 100 个规范 = 600 个生成输出；
  - 正确性包络：基于其中 3 个前沿模型的 300 个输出计算 3 种评分，另加配置感知模式的新输出；
  - 失败分类：对全部失败输出进行自动分类，跨模型、跨难度交叉分析；
  - 通过质量：对 30 个正确输出进行实质性屏幕和突变测试；
  - 难度鲁棒性：50 个样本的人工重标定 + 构造机械难度指标的复现。
- **充分性评价**：
  - **优点**：在精确 oracle 基准中规模较大（1,300 规范），且在统一设置的固定描述上对多个模型进行公平比较；多维度实验覆盖了有效性、正确性、难度、失败模式、通过质量，比较充分。
  - **不足**：每规范只有一次采样，导致二项式采样误差约 ±4 到 7 个百分点，模型间的小差异仅具指示性；主结果只用单一描述提供方（GPT-5）和单一风格（声明式），未检验第二提供方和意图式风格；Gemini-2.5-pro 使用贪婪解码（温度 0），其他模型用默认设置，给跨模型比较引入混淆；难度标签和描述质量审计的标注者包含作者团队成员，并非完全独立。

## 6. 主要结论与发现

- **有效 ≠ 正确**：所有模型生成“能解析”的 TLA⁺ 的频率远高于“能通过模型检查”的频率。最强模型 Claude Opus 4.5 解析率 87%，正确率仅 16%；GPT-5 解析率 89%，正确率仅 4%；开放模型正确率不超过 1%（llama3.3-70b 为 0%）。
- **正确性包络**：同一组 300 个输出，在三种纯评分规则下正确率从 10.0% 降到 1.7%（六倍差距）；加入配置感知规则后，从 18.7% 到 1.7% 形成十一倍差距。这说明“正确率”不是一个单点，而是依赖评测选择的范围。
- **难度悬崖**：基本难度正确率 25%（前沿模型池化），中/高难度骤降至 2%；解析率则保持较高（86%→76%），因此难度主要打击正确性而非有效性。
- **失败模式**：配置绑定失败是主导失败（占前沿模型失败的 64%），解析失败占 23%；三个模型在同一规范上的失败往往重复，说明规范本身驱动失败；Gemini-2.5-pro 有独特的“解析器重失败”指纹。
- **通过质量差**：30 个正确输出中仅 12 个通过实质性屏幕，仅 5 个通过突变测试；因此默认正确率高估真实能力约 2.5 倍。
- **配置感知模式**：提供接口名称后所有模型正确率提升（最强从 16% 到 26%），但排名不变，说明大部分默认模式的失败来自接口恢复而非建模能力。

## 7. 优点

- **执行级精确 oracle**：用 SANY + TLC 对完整可达状态空间进行判定，避免相似度或测试集带来的近似与虚高。
- **基准设计严谨**：显式区分有效性、正确性、实质性和突变存活，并将评分规则作为研究变量而非隐藏假设。
- **真实世界规范**：来自 13 个公共仓库，包含先前 FormalLM 的全部数据，规模超越既有资源。
- **丰富的元数据**：双风格 × 双提供方的描述矩阵、难度标签、类别标签、gold/silver 分层、平凡固定装置标记，支持多种受控研究。
- **失败分类学可追溯**：基于模型检查器输出自动分类，且多数类别有先前文献支撑。
- **开源可复现**：释放规范、描述、模型输出、评分工具和 prompts；通过 SHA-256 确保文件完整性；附带 datasheet 和研究问题目录。
- **思辨性贡献**：“正确性包络”的概念不仅适用于 TLA⁺，也适用于任何用可执行 artifact 评测生成任务的基准设计。

## 8. 不足与局限

- **描述质量局限**：描述由模型生成而非从业者提供，虽有 400 例人工审计（5% 判定为“不忠实”），但并非真实任务场景中的需求描述。
- **评估范围局限**：
  - 主结果仅使用 GPT-5 的声明式描述，未在第二提供方 Claude 的描述上评测，也未运行意图式描述，因此无法检验输入风格/提供方对排名的影响；
  - 多模块组合与细化用例在评估集中代表性不足（100 个中仅 17 个涉及多模块）；
  - 只考察单次采样，没有 pass@k 结果。
- **数据与标注偏差风险**：
  - 难度标签由作者团队按规则分配，人工重检样本小（50 个）且非盲；
  - 描述审计与标签标注含作者参与，可能引入无意识偏向；
  - 数据来自公共仓库，无法排除训练数据污染的可能；作者在发布中嵌入 canary 字符串以检测未来污染，但未进行污染控制实验。
- **评分机制局限**：
  - oracle 是“属性范围”的，只验证配置命名的性质，不验证行为等价；可能因属性过弱而通过；
  - 突变测试被限制为只能在可变更的安全不变量上执行（时态公式无法直接替换为 TRUE），所以 1.7% 是保守下限；
  - 配置绑定失败将“模型建模错误”和“名称不匹配”混在一起，需配置感知模式才能区分。
- **应用限制**：TLA⁺-Bench 旨在作为评测基准，作者明确要求勿作为训练数据；用户若将其用于其他目的，需注意来源仓库的各自许可证。
