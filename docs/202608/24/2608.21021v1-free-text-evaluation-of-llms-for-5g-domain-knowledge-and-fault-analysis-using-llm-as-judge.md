## 摘要
5G及新兴6G网络中的真实故障分析需要领域专家对自由文本诊断（包括根因解释和推荐措施）进行分析。LLM已成为实现此自动化的一种有前景的方法，然而轻量级、可边缘部署的模型是否具备进行深度自由文本诊断的能力仍是一个开放问题。现有基准依赖具有固定答案的限定性选择题，而本文在自由文本生成格式下评估5G领域理解与故障分析。转向这一范式要求在开放式诊断推理上评估轻量级、可边缘部署的AI模型，并建立一个可靠的框架以大规模验证这些文本输出。为此，我们在三个基准（TeleQNA ORAN FT、5G-Faults FT和TeleInter FT）上，评估了三个轻量级LLM（Claude-Haiku-4.5、GPT-5.4-Mini和Gemini-3.1-Flash-Lite）在自由文本5G领域知识与故障分析任务上的表现。三位独立的前沿裁判对输出进行评分，并通过成对裁判间一致性衡量LLM-as-Judge方法的实证有效性。所有三个模型在故障诊断上均达到至少90%的准确率，而3GPP和O-RAN规范的零样本召回率仍是关键差距，所有模型均低于60%。所有运行中裁判间一致性均值至少为0.90，表明多裁判LLM评分能为开放式电信响应提供一致且可复现的评分。在操作上，Gemini-3.1-Flash-Lite提供了最佳效率权衡，兼具竞争力强的准确性与最低的推理成本和延迟，使其成为生产电信部署中最合适的候选者。

## Abstract
Real-world fault analysis in 5G and emerging 6G networks demands domain expertise to analyze free-text diagnostics, including root-cause explanations and recommended actions. LLMs have emerged as a promising approach to automating this, yet whether lightweight, edge-deployable models are capable of performing in-depth free-text diagnostics remains an open question. While existing benchmarks rely on restrictive MCQs with fixed answer keys, this paper evaluates 5G domain understanding and fault analysis in a free-text generation format. Transitioning to this paradigm requires evaluating lightweight, edge-deployable AI models on open-ended diagnostic reasoning, alongside a dependable framework to validate these text outputs at scale. To address this we evaluate three lightweight LLMs, Claude-Haiku-4.5, GPT-5.4-Mini, and Gemini-3.1-Flash-Lite, on free-text 5G domain knowledge and fault-analysis tasks across three benchmarks, TeleQNA ORAN FT, 5G-Faults FT, and TeleInter FT. Three independent frontier judges score outputs, and pairwise inter-judge agreement is measured as an empirical test of the LLM-as-Judge methodology. All three models reach at least 90% accuracy on fault diagnosis, while zero-shot recall of 3GPP and O-RAN specifications remains the critical gap, with all models scoring below 60%. Mean inter-judge agreement is at least 0.90 across all runs, indicating that multi-judge LLM scoring produces consistent, reproducible grades for open-ended telecom responses. Operationally, Gemini-3.1-Flash-Lite offers the best efficiency trade-off, combining competitive accuracy with the lowest inference cost and latency, making it the most suitable candidate for production telecom deployments.

## 1. 核心问题与整体含义

- **背景与动机**：随着 5G/6G 网络复杂度持续上升，故障管理（如切换流程、会话建立、核心网信令故障）越来越依赖领域专家对自由文本诊断信息（根因解释、推荐动作）进行分析。LLM 被视为自动化根因分析（RCA）的潜在手段，ETSI 等组织也强调轻量、高效模型对实现网络自治的重要性。
- **现有评估方式的缺陷**：目前主流的电信领域 LLM 基准（如 TeleQNA、ORAN-Bench-13K、Tele-LLMs、6G-Bench）几乎全部采用有固定答案的多选题，无法还原真实故障分析中开放式、非结构化文本输出的场景，也无法可靠地衡量模型“生成解释与诊断步骤”的能力。
- **研究问题**：
  1. 轻量级、边缘可部署的 LLM 能否胜任 5G 规范知识问答与故障分析？
  2. 多个前沿 LLM 作为裁判时，彼此之间是否有一致的评分结果？
- **整体含义**：该研究首次在电信域尝试"自由文本生成 + 多裁判 LLM 自动评分"的评测范式，为轻量级模型在真实运维场景中的可行性和可信评估提供了实证依据。

## 2. 方法论

- **总体框架**：基于 UK AI Security Institute 的 Inspect AI 实验框架，构建两阶段评估管线：
  - **Solver 阶段（学生模型生成）**：
    - 使用 `prompt_template()` 注入专家电信系统提示；
    - 使用 `chain_of_thought()` 强制学生模型输出两段式结构：
      - `Student Explanation`（2 行内解释）
      - `Student Answer`（1 行最终答案）
    - 通过 `generate()` 调用 API 获取生成结果；
  - **Scorer 阶段（裁判模型评分）**：
    - 三个前沿裁判模型并行独立打分；
    - 每个裁判接收原始问题、学生解释、学生答案和参考正确答案，以电信领域专家身份作二分类评分（Correct / Incorrect）；
    - 输出经正则解析，`C` 映射为 1.0，`I` 映射为 0.0。
- **学生模型**：Claude-Haiku-4.5、GPT-5.4-Mini、Gemini-3.1-Flash-Lite，均通过 OpenRouter 统一 API 调用，零样本推理，不使用 RAG、few-shot 或工具。
- **裁判模型**：GPT-5.5、Gemini-3.1-Pro-Preview、Gemini-3.5-Flash，同样通过 OpenRouter 路由。
- **评价指标**：
  - 准确率：`Acc_j = mean(s_i,j)`，并对三个裁判取平均；
  - 裁判间一致性：任意两个裁判对每个样本是否同分，`P(a=b) = mean(c_i,a,b)`；
  - Token 用量（推理/完成 token 总量）；
  - 平均生成延迟（秒/样本）；
  - API 推理成本（美元/100 样本）。

## 3. 实验设计

- **数据集**：共三个基准，每个基准抽取 100 条，并将原有多选题选项全部移除，强制模型以自由文本作答。
  - **TeleQNA ORAN FT**：来自 3GPP 5G / O-RAN 规范，考查规范、协议、接口、架构等事实性知识；
  - **5G-Faults FT**：来自真实 5G 故障日志场景，要求模型判断故障原因、受影响组件及修复措施；
  - **TeleInter FT**：面向 OEM/网络工程师场景的概念解释题，兼顾事实记忆与技术理解。
- **对比方案**：以三个轻量级模型作为学生模型，在三个数据集上两两组合，共 9 组实验；没有引入其他评测方法（如 ROUGE、人类打分）作为对照，而是通过三个独立裁判模型交叉验证评分结果。
- **主要比较维度**：准确率、裁判间一致性、API 成本、延迟、token 使用量。

- **实验组数**：3 个学生模型 × 3 个数据集 = 9 组完整评估；每组 100 个样本，共约 900 次学生模型生成，每次生成由 3 个裁判打分，合计约 2700 次裁判评分。
- **覆盖面**：合理覆盖了规范知识、故障诊断和网络概念解释三类核心电信任务；同时衡量了准确率、一致性、成本、延迟和 token 使用，维度较广。

  - 未进行消融实验（如单裁判 vs 多裁判、不同提示策略、是否有 RAG/微调等）；

## 6. 主要结论与发现

- **故障诊断能力较强**：在 5G-Faults FT 上，所有三个模型准确率均≥90%；GPT-5.4-Mini 达到 98.3%。
- **规范知识零样本召回是短板**：TeleQNA ORAN FT 上所有模型准确率均低于 60%，表明轻量模型无法可靠地零样本回忆 3GPP/O-RAN 规范细节，需借助 RAG 或领域微调。
- **模型总体排序**：GPT-5.4-Mini 总体准确率最高（82.1%），Gemini-3.1-Flash-Lite 次之（78.1%），Claude-Haiku-4.5 相对落后（71.0%）。
- **多裁判评估可靠**：所有 9 组运行中，裁判间平均一致性均≥0.90；其中 Gemini-3.1-Pro 和 Gemini-3.5-Flash 之间一致性最高（0.95–0.99）。
- **重要发现**：在 Claude-Haiku-4.5 的 5G 故障诊断上，GPT-5.5 与两个 Gemini 裁判在部分样本上系统性分歧（GPT-5.5 给出 82% vs Gemini 约 94%），印证了单裁判评测可能掩盖模型偏见，多裁判结构是必要的。
- **部署建议**：Gemini-3.1-Flash-Lite 在保持较高准确率的同时，具有最低的推理成本、最低延迟和最少的 token 输出，是生产环境中性价比最优的选择。

## 7. 优点

- **填补空白**：首次将电信领域 LLM 评估从固定答案选择题推进到开放式自由文本，更贴近真实故障诊断场景。
- **多裁判设计**：使用三家提供商的三个前沿裁判模型独立评分，并计算两两一致性，能暴露单一裁判系统的偏见（如 GPT-5.5 与 Gemini 在故障响应上的分歧）。
- **兼顾学术与运维**：同时报告准确率、裁判一致性、API 成本、延迟和 token 用量，直接回应边缘部署的工程需求。
- **端到端可复用**：基于 Inspect AI 构建，数据集和代码使用公开组件，日志格式持久化，便于复现和扩展。
- **提示设计合理**：强制两段式输出，将解释与最终答案分离，使裁判可以基于最终答案打分，降低推理过程对评分的干扰。

## 8. 不足与局限

- **缺乏人类专家验证**：论文只证明裁判间一致性高，无法判断裁判评分是否与真实电信专家的判断一致，有待后续人工标注验证。
- **样本规模有限**：每个基准仅 100 条，样本量较小，可能无法反映真实分布的多样性，也缺少置信区间等统计支撑。
- **评测范围窄**：仅覆盖三个轻量模型，未与大型前沿模型（如 GPT-5.5 本身作为学生模型）或 RAG/微调后的模型进行对比；零样本条件也限制了结论的外推性。
- **裁判偏差风险未完全消除**：LLM-as-Judge 常存在位置偏好、长度偏好、自增强偏差等问题，论文虽采用多裁判缓解，但没有对这些偏差做专门分析。
- **缺少消融和敏感性分析**：没有测试不同提示模板、不同温度、不同裁判组合对结果的影响，无法说明评测结果的稳健性。
- **成本核算依赖外部网关**：API 成本和延迟基于 OpenRouter 日志，不同时段、不同模型版本可能波动，结论的可复现性依赖第三方服务稳定性。
