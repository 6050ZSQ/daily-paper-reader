## 摘要
大型语言模型（LLM）在API调用方面的可靠性在多语言环境中会下降。一个常见的失败模式是，模型选择了正确的工具，但生成的参数值使用了不一致的语言，我们称之为参数语言不匹配（ALM）。尽管这些输出在语义上是正确的，但在操作上无效，并且不会被标准的API调用指标所捕获。我们重新审视了缓解ALM的后训练策略，并发现，在我们的基准测试中，监督微调（SFT）提供了一个强大的基线，显著提高了参数语言一致性和端到端函数调用准确性。在一致的模型选择下，SFT的性能与更复杂的强化学习（RL）方法相当，有时甚至超过它们。我们进一步考察了具有结构化、参数感知奖励的RL是否带来额外的好处。虽然诸如组相对策略优化（GRPO）之类的方法可以提高语言一致性并更好地保留通用推理能力，但这些增益是渐进的，并且在泛化和多目标权衡中最为显著。总体而言，我们的结果表明，多语言API接地的大部分性能可以通过仔细的监督训练来实现，而RL提供的是有针对性的改进，而非根本性的改进。

## Abstract
The reliability of Large Language Models (LLMs) for API calling degrades in multilingual settings. A common failure occurs when a model selects the correct tool but generates argument values in an inconsistent language, which we term Argument Language Mismatch (ALM). Although semantically correct, such outputs are operationally invalid and not captured by standard API-calling metrics. We revisit post-training strategies for mitigating ALM and find that, in our benchmark, supervised fine-tuning (SFT) provides a strong baseline, substantially improving argument language consistency and end-to-end function call accuracy. Under consistent model selection, SFT achieves performance comparable to, and sometimes exceeding more complex reinforcement learning (RL) approaches. We further examine whether RL with structured, argument-aware rewards offers additional benefits. While methods such as Group Relative Policy Optimization (GRPO) can improve language consistency and better preserve general reasoning ability, these gains are incremental and most pronounced in generalization and multi-objective trade-offs. Overall, our results suggest that much of the performance in multilingual API grounding can be achieved through careful supervised training, with RL providing targeted rather than fundamental improvements.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究痛点**：大型语言模型（LLM）在API调用中可靠性会随语言环境改变而下降。当用户使用非英语语言发出请求时，模型经常出现一类独特且被忽视的失败——**参数语言不匹配（Argument Language Mismatch, ALM）**。
- **ALM 定义**：模型选对了工具（API），甚至正确填入了参数名，但参数值却使用了与用户输入不一致的语言。例如，西班牙语用户问"15000欧元兑换多少美元"，模型返回的参数值是 `to currency='dólares'`（应为西语）却生成为 `'dollars'`。
- **关键特征**：这类输出**语义正确但操作无效**——真实系统会因语言约束而拒绝执行；更关键的是，**标准API调用指标无法捕获这种错误**，会将其归并为一般性调用失败。
- **研究问题**：鉴于近年来强化学习（RL）在复杂生成任务中的热度，一个自然的问题是——**解决ALM是否必须依赖复杂的RL方法？还是仔细的监督微调（SFT）就足够了？**
- **核心发现（一句话概括）**：SFT已构成强大的基线，其性能与更复杂的RL方法相当甚至更优；RL（尤其GRPO）仅带来**增量性**改进，主要体现于泛化能力和多目标权衡的保持。

## 2. 方法论

### 2.1 问题形式化

- 将多语言API调用建模为结构化预测问题：模型需将自然语言用户请求 u 映射为一系列API调用 `Y = {(f1,a1),...,(fm,am)}`，其中每个参数值携带语言属性。
- **约束条件**：源自用户的参数值应满足 `lang(v) = lang(u)`，除非API规范明确要求其他语言。
- 引入了**层次化评估指标**，用于隔离ALM错误：

| 指标 | 含义 | 层级 |
|------|------|------|
| TID (Tool Invocation Detection) | 是否正确判断需要调用API | 高 |
| TSA (Tool Selection Accuracy) | 是否选对API | ↓ |
| ACA (Argument Completion Accuracy) | 是否补全所有参数名 | ↓ |
| ALC (Argument Language Consistency) | 参数值语言是否与用户一致 | ↓ |
| FCM (Function Call Match) | 完整调用是否匹配 | 低 |

- 指标呈严格层级关系：`FCM ≤ ALC ≤ ACA ≤ TSA ≤ TID`。

### 2.2 训练方法

论文系统比较了两类后训练范式：

1. **监督微调（SFT）**：最大化ground-truth结构化输出的对数似然。SFT通过曝露平行示例隐式学习参数语言对齐。
2. **强化学习（RL）**：让模型采样候选API调用并接收结构化奖励。比较了两种优化算法：
   - **PPO**（近端策略优化）：使用裁剪的目标函数与KL正则化，单样本采样，批级别归一化优势。
   - **GRPO**（组相对策略优化）：对同一提示采样K个输出，在组内进行相对比较来计算优势，不需要价值网络。

### 2.3 奖励设计（核心创新）

论文设计了**三种粒度递增的奖励函数**：

- **RM-1（稀疏二元奖励）**：仅区分全对（+2.0）、仅语言错（0.0）、结构错（-1.0）。信号过于粗糙。
- **RM-2（层次化阶梯奖励）**：沿 TID→TSA→ACA→ALC→FCM 层次给予阶梯得分（-1.0到+2.0），并引入连续ALC评分（LLM裁判给出 2.0/1.5/1.0 的语言得分）。
- **RM-3（参数分解奖励）**：将奖励**分解到每个独立参数值**上——裁判对每个参数值给出 2.5/2.0/1.0 的语言评分，结构门控通过后取参数级得分的平均值。实现了**细粒度的信用分配**。
- **Token级奖励加权**：额外引入超参数 β，对参数值对应的token施加更高权重（β ∈ {1.5, 3}）。该技术对GRPO有效但对PPO具有破坏性。

### 2.4 训练流程

- 可选SFT暖启动（1 epoch）→ RL训练（θ0 ← SFT，然后进行PPO/GRPO更新，带KL约束到参考策略）。

## 6. 主要结论与发现

1. **SFT是强基线**：在一致模型选择下，SFT可达79.1 ALC / 67.4 FCM，**超过GRPO（74.0/55.3）**，表明大量ALM可通过模仿学习解决。
2. **RL收益是增量的而非根本性的**：RL（尤其GRPO）相对SFT的改进有限，且主要体现于泛化（Split-2）和推理能力保持。
3. **奖励粒度是RL性能的关键驱动因素**：RM-3（参数分解奖励）> RM-2（层次阶梯）> RM-1（稀疏），每级提升均显著。
4. **GRPO优于PPO**：尤其在使用细粒度token加权时，GRPO稳定且有效（ALC 77.74），而PPO会崩溃（ALC 50.81）。
5. **RL更擅长跨语言泛化**：GRPO在意大利语、荷兰语上均高于SFT，学习的是"参数语言匹配用户语言"的抽象规则而非表面形式记忆。
6. **推理保持**：GRPO几乎不损伤英文推理（70.8→70.4），而SFT显著下降（70.8→62.2）。
7. **模型规模弥补**：7B + GRPO（68.10 ALC）可接近甚至超过14B + SFT（74.47）的部分表现。
8. **ALM贡献分析**：30-50%的残余API失败可归因于参数语言不匹配，在RL训练后ALM成为主导失败模式。

- **基准单一性**：仅使用BFC一个基础数据集进行扩展，结论是否适用于APIGen、ToolBench等其他函数调用基准尚不明确。

- **算力信息不透明**：未提供任何GPU配置、训练时间、参数规模对应的资源需求，不利于复现和成本评估。
- **RL收益的普遍性存疑**：论文的结论（RL是增量的）可能限于"参数语言一致性"这类表层对齐问题；对需要长程推理或复杂信用分配的任务，结论未必适用。

- **模型选择标准单一**：以验证FCM选择检查点，可能对ALC的优化产生次优选择。

该论文通过严格的对照实验，为"多语言API调用中的后训练策略选择"这一实际工程问题提供了难得的系统性证据：**复杂的RL方法并非解决参数语言不匹配的必要条件，SFT加细心数据准备即可实现大部分性能提升**。论文的贡献不仅在于发布了一个可复现的多语言基准与细粒度评估框架，更在于其"先审视SFT上限，再判断RL增量"的研究范式——这对更广泛的结构化生成任务（如代码生成、语义解析）的后训练设计具有借鉴意义。
