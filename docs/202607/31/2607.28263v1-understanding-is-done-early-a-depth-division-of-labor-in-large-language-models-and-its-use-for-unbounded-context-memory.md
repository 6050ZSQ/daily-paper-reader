## 摘要
Transformer的深度并非均匀使用：较低层和中间层构建语义表示，而较高层则逐渐为预测而专门化这些表示。我们将这种分工转化为CoMem（理解记忆），它仅通过中间层写入每个上下文块，检索固定数量的缓存残差状态，并在结果打包上重新计算查询条件下的较高层。对于固定的检索预算，模型侧的读取计算和内存与存储的上下文长度无关。我们在统一的、无聊天模板的协议下评估了持续训练的Qwen3-8B基础语言模型。主干网络被冻结；旗舰模型仅在普通PG19上训练秩为32的自蒸馏LoRA，我们单独报告一个无适配器的分支。CoMem在RULER上达到97.05，在LoCoMo上达到38.27，而全上下文KV-Direct为34.59；对话记忆优势在对话簇重采样和独立评判下依然存在。在额外长上下文和长文档任务上的结果既展示了有界检索的好处，也揭示了其窗口内压缩代价。受控深度扫描表明，更深的缓存降低了每次查询的重计算，但引入了保真度损失，而自蒸馏可大幅修复该损失。在NVIDIA H20上128k长度的独立无适配器效率控制中，CoMem使用18.26 GB而非89.36 GB，并实现了7.83倍的预填充加速。这些结果表明，长上下文记忆可以沿层轴而非仅沿令牌轴进行组织。

## Abstract
Transformer depth is not used uniformly: lower and middle layers build semantic representations, while upper layers increasingly specialize them for prediction. We turn this division of labor into CoMem (Comprehension Memory), which writes each context chunk only through an intermediate layer, retrieves a fixed number of cached residual states, and recomputes the query-conditioned upper layers over the resulting pack. For a fixed retrieval budget, model-side read compute and memory are independent of stored-context length. We evaluate a continued-trained Qwen3-8B base LM under a unified chat-template-free protocol. The backbone is frozen; the flagship trains only a rank-32 self-distillation LoRA on plain PG19, and we report an adapter-free arm separately. CoMem reaches 97.05 on RULER and 38.27 on LoCoMo versus 34.59 for full-context KV-Direct; the dialogue-memory advantage survives conversation-cluster resampling and an independent judge. Results on additional long-context and long-document tasks expose both the benefits of bounded retrieval and its in-window compression tax. Controlled depth sweeps show that deeper caching lowers per-query recomputation but incurs a fidelity loss that self-distillation substantially repairs. In a separate adapter-free efficiency control on an NVIDIA H20 at 128k, CoMem uses 18.26 GB rather than 89.36 GB and achieves a 7.83x prefill speedup. These results show that long-context memory can be organized along the layer axis, not only the token axis.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：长上下文语言建模面临两大核心瓶颈——自注意力机制带来的**二次方预填充计算成本**（quadratic prefill cost），以及键值缓存（KV cache）带来的**线性内存增长**。此外，模型还受限于骨干网络的原生位置编码窗口（如 Qwen3-8B 为 40,960 token，131,072 上限需 YaRN 扩展且未激活）。
- **现有方法的不足**：主流长上下文记忆方法沿 **token 轴**组织——要么驱逐或压缩 KV 状态（如 StreamingLLM、H2O、SnapKV、PyramidKV），要么检索相关文本或记忆单元（如 RAG、InfLLM），要么写入训练好的记忆池（如 MemoryLLM）。这些方法的模型侧读取计算和内存均随存储上下文长度线性增长。
- **核心洞察（深度分工）**：Transformer 的深度并非均匀使用——**较低层和中间层使语义信息可访问，而上层逐渐将其专门化为当前查询和预测服务**。这一深度层面的分工长期未被系统性地用于长上下文记忆设计。
- **整体含义**：论文提出，长上下文记忆不仅可以沿 token 轴组织，也可以沿 **layer 轴（深度轴）** 组织。通过"浅层写入 + 深层按需重计算"的深度分区，可以在固定检索预算下，使模型侧读取计算和内存与存储上下文长度**完全解耦**，实现真正意义上的"有界读取、无界上下文"。

## 2. 方法论：CoMem（Comprehension Memory）

### 2.1 核心思想

CoMem 将 Transformer 沿深度方向一分为二：
- **Write（写入）**：每个上下文块仅通过前 \( j \) 层（浅中层），缓存每 token 的残差张量 \( h_j \)，此时语义信息已可访问。
- **Read（读取）**：检索固定数量的相关缓存残差张量，与查询打包后，仅重计算第 \( j \) 层到最后一层（上层），使上层在查询存在的情况下进行预测特化。

### 2.2 关键技术细节

**（1）存储效率公式**

\[
\frac{|h_j|}{|KV|} = \frac{d}{2L \cdot d_{kv}} = \frac{n_q}{2L \cdot n_{kv}}
\]

对 Qwen3-8B（\( d=4096, L=36, n_q=32, n_{kv}=8 \)），每个 token 的缓存状态仅为完整 bf16 KV 的 **1/18**（8 KB vs. 144 KB/token）。

**（2）Write 流程**
- 文档被分割为不相交的 c-token 块（旗舰为 512）。
- 每块从零开始重新设置 RoPE 位置，通过 layers[0:j] 前向计算，将 \( h_j \) 写入外部存储，以文本为键索引。
- Write 成本与上下文长度线性，仅执行 j 层，且可离线复用。

**（3）Read 流程**
- 使用迭代 BM25 检索 top-k 相关块（旗舰 k=12，hop width=4，3 轮自动前沿扩展去重）。
- 打包结构：`[sink; 选中的 h_j; 查询的 h_j]`，使用全新的连续 RoPE，以文档顺序排列。
- 对 layers[j:L] 执行**全跨块因果注意力**，允许后续块和查询整合早期证据。
- 读取包长度固定：\( |pack| = \text{sink} + k \cdot c + \text{query} \approx 6.7k \)，**与存储上下文长度无关**。
- 生成阶段：仅做一次上层 KV 预填充，后续解码使用查询本地下层缓存，解码工作量与存储长度无关。

**（4）自蒸馏（Self-Distillation）**
- 训练秩 32 LoRA（α=64，零 dropout）于 Qwen3-8B 的 layers[12:35] 上（约 5820 万可训练参数，占 0.71%）。
- 目标：学生（j=12）匹配冻结教师（j=0）在教师 top-64 logit 支持上的分布。
- 损失函数：双向 KL 散度 \( L_{distill} = 0.6 \cdot KL(p\parallel q) + 0.4 \cdot KL(q\parallel p) \)，无交叉熵项。
- 训练数据：仅 PG-19 普通文本，2,048 token 窗口（4 个 512 token chunk），**无任何合成长上下文示例、检索或任务监督**。
- 作用：将零样本可读深度推向更深层，修复深层缓存的状态保真度。

**（5）深度分割 j 作为质量-成本旋钮**
- j=0 等价于选择性全前向（max|Δlogit| < 10⁻⁴）；j=L 则无上层重计算。
- 越深的分割 → 每查询重计算越少，但零样本可读性越差；自蒸馏可将操作点推向更深。

## 3. 实验设计

### 3.1 基准与数据集

| 基准 | 任务类型 | 长度范围 |
|------|----------|----------|
| **RULER** | 合成长文本（单针、多键、变量追踪） | 8k–128k（另有 256k 扩展） |
| **LongEval** | 行检索 | 4k–128k |
| **LongBench** | 6 个文档 QA 数据集（NarrativeQA、Qasper、HotpotQA、2Wiki、MultiFieldQA、Musique） | 常规长文档 |
| **BABILong** | 推理任务（qa1/qa2/qa5） | 0k–32k |
| **LoCoMo** | 长对话记忆（1,986 个 QA 对，10 个对话簇，5 个类别） | 长对话 |

### 3.2 统一评估协议

- 所有方法均在 **chat_template=False**（禁用聊天模板）的统一纯文本协议下评估。
- 骨干网络为 Qwen3-8B base LM（已持续训练，无 SFT/RL）。
- 旗舰配置：j=12、chunk=512、top-12 BM25、BOS sink、贪心解码。
- RULER 使用官方 string_match_all；BABILong 使用 compare_answers + TASK_LABELS（不使用 re.search）；LoCoMo 以 GPT-4o 语义评判为主要指标，token F1 和子串准确率为辅助词汇诊断。

### 3.3 对比方法

- **KV-Direct**（Qasim et al., 2026）：从残差流精确重建完整 KV 的全上下文方法（原生 RoPE、无 YaRN，超出 40,960 视为压力参考）。
- **HCache-style**（Gao et al., 2025）：缓存中间激活并重计算上层，但无检索、无训练。
- **StreamingLLM**（Xiao et al., 2024b）：注意力 sink + 最近窗口。
- **InfLLM**（Xiao et al., 2024a）：token 级记忆单元检索。
- **MemoryLLM**†（Wang et al., 2024）：Llama-3-8B-chat 骨干上的固定大小潜在池（跨骨干参考）。

### 3.4 主要实验结果

- **核心基准**：CoMem（+LoRA）在 RULER 上 97.05、LongEval 69.0、LongBench 12.15、BABILong 50.43、LoCoMo 38.27，五基准平均 **53.38**，大幅超越 KV-Direct（50.75）和所有基线。
- **对话记忆**：CoMem 的 LoCoMo Judge 38.27 vs. KV-Direct 34.59；配对的 1,540 个可回答项上 +4.81 分，item-bootstrap 95% CI [2.34, 7.27]；10 对话簇 bootstrap 仍为正；DeepSeek-V3 独立审计保持排序。
- **效率**：128k 时 prefill 加速 7.83×、峰值显存 89.36→18.26 GB；解码速度与 Dense 相当或更快。
- **消融/机制**：深度扫描、检索宽度、跨块注意力、自蒸馏效果等均有受控对比。

- MemoryLLM 使用不同骨干（Llama-3-8B-chat）且无聊天模板属于分布外调用，仅作诊断参考。

## 6. 主要结论与发现

1. **深度分工是真实且可利用的**：语义内容深度在 Qwen3 0.6B–32B 范围内近似尺度不变（≈0.45L），而零样本可读深度随模型规模单调加深（0.09L→>0.42L）；两者之间的差距即为适配器可修复的"适应空间"。
2. **选择（retrieval）而非保真度（fidelity）是长距离瓶颈**：Oracle 检索在 RULER 单针任务上始终 100%，而 recency 和 reader-attention 选择器在 32k 时显著退化。
3. **CoMem 实现有界读取下的高效记忆**：128k 上下文时模型侧读取包仅 ~6.5k token，显存从 89.36 GB 降至 18.26 GB，prefill 加速 7.83×，且对话记忆质量反而优于全上下文 KV-Direct。
4. **自蒸馏显著修复深层读取保真度**：在相同 j=12 下，PG-19-only LoRA 恢复 LoCoMo 13.75 分、BABILong qa1/qa2/qa5 各 22.2/9.0/8.4 分，证明是接口适配而非任务特定训练。
5. **更深的缓存并非免费午餐**：深度切割降低每查询计算（j=12 比 j=0 的 128k Read 降 29%），但冻结状态下以质量下降为代价；**质量-内存-计算存在真实权衡**。
6. **更多检索并非总是更好**：~17k 的宽检索在 16k 起反而劣于 ~6.5k 的聚焦检索（额外干扰链）。
7. **跨块注意力对多事实消歧至关重要**：块对角替代全注意力导致多键检索损失 36/62 分（8k/16k）。

## 7. 优点

1. **概念创新**：首次系统性地将"深度分工"（layer-axis division of labor）作为长上下文记忆的组织原则，开辟了"层轴记忆"这一新方向，而非沿 token 轴的增量改进。
2. **理论解释与工程实现的闭环**：从可解释性观测（probe、因果截断、深度扫描）出发，推导出具体的内存架构设计，并给出严格的存储效率公式。
3. **训练效率极高**：仅 2.9 H20 GPU 小时的 PG-19 LoRA 训练即取得显著效果，无合成数据、无任务监督，实用性强。
4. **实验设计严谨**：统一协议、受控消融（同包同深度）、统计不确定性分析（bootstrap/簇重采样/独立审计）、跨规模跨架构泛化验证，在同类工作中属于上游水平。
5. **诚实披露局限**：明确区分"无扩展压力参考"与"长度扩展上界"，不夸大结论；报告未记录的总 GPU 小时
