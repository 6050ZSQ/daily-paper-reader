## 摘要
大型语言模型及基于LLM的智能体被广泛用作个人聊天助手、企业副驾驶和自主工作流智能体。在所有这些应用中，记忆（即在长上下文和多次交互中积累的信息的保留、访问和推理能力）对决定智能体的可靠性起着关键作用。我们提出了RECON（面向混淆叙事的长上下文推理），这是一个用于评估长上下文组合推理的基准测试。RECON涵盖三个领域（刑事、医疗和金融）的24个案例文件，每个文件包含50k到100k个token，并测试智能体在六项记忆密集型任务上的表现：重建多跳证据链、传播级联失效、解决源冲突、反事实推理、满足时间约束和时间事实检索。近期的记忆基准测试评估智能体能否检索散落的事实或检测事实是否发生变化，而RECON评估变化发生后会发生什么——智能体能否追踪哪些下游结论受到影响，哪些结论因独立支持而幸存，以及替代时间线本会如何展开。我们的评估揭示了当前架构的显著局限性：即使最强的非Oracle系统也仅达到22.4%的准确率，检索和推理各自成为挑战。

## Abstract
Large language models and LLM-based agents are widely used as personal chat assistants, enterprise copilots, and autonomous workflow agents. In all these applications, memory (the ability to retain, access, and reason over information accumulated over long contexts and multiple interactions) plays a crucial role in determining the reliability of any agent. We introduce RECON (Reasoning over Extended Contexts with Obfuscated Narratives), a benchmark for evaluating compositional reasoning over long contexts. RECON spans 24 case files across three domains (criminal, medical, and financial), each ranging from 50k to 100k tokens, and tests agents on six memory intensive tasks: reconstructing multi-hop evidence chains, propagating cascading invalidations, resolving source conflicts, counterfactual reasoning, satisfying temporal constraints, and temporal fact retrieval. Recent memory benchmarks evaluate whether agents can retrieve scattered facts or detect if a fact has changed whereas RECON evaluates what happens after the change, whether agents can trace which downstream conclusions are affected, which survive through independent support, and how alternative timelines would have unfolded. Our evaluation reveals substantial limitations across current architectures: even the strongest non-Oracle system reaches only 22.4% Accuracy, with retrieval and reasoning each surfacing as challenges.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有的 LLM 智能体（如 ChatGPT、Claude、企业副驾驶等）在长上下文和多次交互中，需要具备“记忆”能力来保留、访问和推理累积的信息。当前记忆基准主要评估智能体能否检索散落的事实或检测事实是否变化（状态机视角），但忽略了 **事实间的交互、矛盾、级联失效**：例如，在刑事、医疗、金融等高风险场景中，一个证据被修改或推翻后，智能体需要追踪哪些下游结论被影响、哪些幸存、替代时间线会如何变化。现有基准没有捕捉这种 **组合推理** 需求。
- **整体含义**：作者提出 RECON（Reasoning over Extended Contexts with Obfuscated Narratives），一个全新的基准，将记忆建模为 **溯源图（provenance graph）** 而非状态机，要求智能体在动态文档中推理依赖关系、矛盾传播和反事实情景。这更贴近真实应用中的记忆挑战，且揭示当前系统的严重不足。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：构建 24 个长文案卷（50k–100k tokens 各），覆盖刑事、医疗、金融三个领域。每个案例包含显式的溯源图（证据链、失效、冲突、反事实依赖、并行时间流）。所有 ground-truth 答案由确定性代码从图中计算得出，不依赖 LLM 生成。LLM 仅用于受约束的自然语言表面实现。
- **生成流程**（六阶段确定性管线）：
  1. **属性条件化蓝图合成**：用带前置条件/后置条件的产生式规则，从种子配置生成案例蓝图。
  2. **骨架扩展与时间强制**：生成带时间戳的事件、证据、依赖、失效、冲突、反事实、并行流，强制时间单调性。
  3. **溯源 DAG 与证明迹**：骨架导出全局有向无环图，边表示因果、修正、无效、解决关系。每个问题附带最小证明子图。
  4. **确定性任务合成**：从 DAG 生成六类测试题，使用固定配额矩阵保证分布稳定。
  5. **语言实现**：LLM（多家族轮换）将骨架转化为调查风格散文，仅改措辞，不改变事实。
  6. **验证**：六阶段验证（语法、结构、溯源、LLM 语义审计、鲁棒性、人工）。
- **六类任务**：
  - **链重建**（5–15 跳证据链因果排序）
  - **级联传播**（失效后哪些结论倒塌/幸存）
  - **源冲突解决**（利用独立佐证证据裁决矛盾）
  - **反事实推理**（若早期发现时间改变则后续如何变化）
  - **时间约束满足**（跨并行数据流满足时间窗口）
  - **时间事实检索**（基线：顺序、时间点状态等）

## 3. 实验设计：数据集、基准、对比方法

- **数据集**：RECON 包含 24 个文案卷，两个领域各 8 个，每个 50k–100k tokens，共 1,604 个问题（经污染过滤后 1,414 个）。所有答案完全确定且唯一。
- **基准与对比方法**：

## 6. 论文的主要结论与发现

1. **RECON 极具挑战性**：所有非 Oracle 系统 Accuracy 均低于 25%，最高仅 22.4%（Gemini-2.5-Pro）。Oracle 也只有 54.6%，说明推理本身即使有完美检索也是瓶颈。
2. **不同架构各有所长**：长上下文在多源推理（链重建、源冲突、反事实、时间约束）领先；RAG 在时间事实检索上最优（混合+重排序 0.443）；记忆系统在 **级联传播** 上表现出色（Supermemory 0.708）。
3. **检索是必要非充分条件**：检索命中的问题中仍有约 80% 回答错误，说明推理才是主要瓶颈（图3）。
4. **反事实推理是硬天花板**：Oracle 在反事实任务上也仅 48.3%，证明组合推理深度挑战大。
5. **链长增大导致性能下降**：Oracle 准确率从 100%（3-4 跳）降至 50%（10 跳），非Oracle 则几乎全线在 0–16%。
6. **记忆系统 token 效率高但压缩丢失连接**：记忆仅用 3k–8k tokens/问，比长上下文（64k–70k）效率高一个数量级，但在链重建和源冲突上严重不足。

## 7. 优点：方法或实验设计上的亮点

- **诊断分析深入**：不仅报告总体性能，还分解检索 vs 推理、链长效应、不同架构优势区域。
- **开放性与透明度**：代码、基准、评估框架全部公开，鼓励社区复现与改进。
