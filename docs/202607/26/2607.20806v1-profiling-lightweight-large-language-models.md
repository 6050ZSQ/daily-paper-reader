## 摘要
轻量级大型语言模型（LLM）正越来越多地被部署在个人计算机上本地运行，并有望在资源受限的边缘和移动环境中发挥越来越大的作用。在此类场景中，能耗、执行时间和内存使用直接影响实际可用性，然而现有对LLM效率的评估主要依赖参数数量或FLOPs等代理描述符，这些通常与任务精度脱钩。本文介绍了一种基于PTME的实验框架，用于对轻量级LLM推理进行精度感知的性能剖析，通过直接硬件级测量联合测量精度、执行时间、峰值内存使用和能耗。该方法应用于一组具有代表性的轻量级LLM，这些模型在受控桌面平台上的边缘类资源约束下本地执行，使用的基准测试涵盖代码生成、数学推理和多任务理解。我们发现，静态代理描述符能较好地近似推理成本，但无法预测精度。收紧资源约束会增加成本而不影响精度，对执行时间的放大作用强于对能耗的影响，且对较大模型的惩罚最严重。此外，没有任何单一模型在所有PTME维度上占优，帕累托分析揭示了仅通过精度或效率评估会隐藏的非支配配置，为在不同资源约束下选择模型提供了实用指导。这些结果表明，仅凭大小、FLOPs、延迟或精度来选择轻量级LLM可能会选错部署候选；PTME性能剖析能揭示以较低物理成本保留有用精度的配置。

## Abstract
Lightweight large language models (LLMs) are increasingly being deployed locally on personal computers and are expected to play a growing role in resource-constrained edge and mobile environments. In such settings, energy consumption, execution time, and memory usage directly affect practical usability, yet existing evaluations of LLM efficiency largely rely on proxy descriptors such as parameter count or FLOPs, often decoupled from task precision. This paper introduces a PTME-based experimental framework for the precision-aware profiling of lightweight LLM inference, jointly measuring Precision, execution Time, peak Memory usage, and Energy consumption through direct hardware-level measurements. The methodology is applied to a representative set of lightweight LLMs executed locally under edge-class resource envelopes on a controlled desktop platform, using benchmarks spanning code generation, mathematical reasoning, and multi-task understanding. We find that static proxy descriptors approximate inference cost well but fail to predict precision. Tightening the resource envelope increases cost without affecting precision, amplifying execution time more strongly than energy and penalizing larger models the most. Moreover, no single model dominates across all PTME dimensions, and a Pareto analysis reveals non-dominated configurations that would be hidden by accuracy-only or efficiency-only assessments, providing practical guidance for selecting models under different resource envelopes. These results show that selecting lightweight LLMs by size, FLOPs, latency, or accuracy alone can select the wrong deployment candidate; PTME profiling exposes configurations that preserve useful accuracy at lower physical cost.

## 论文提出的方法论

### 核心思想
提出 PTME 框架，将 **P（精度）、T（时间）、M（峰值内存）、E（能耗）** 四个维度联合测量并分析。不同于只关注模型规模或单个运行指标，PTME 强调**精度与物理成本必须同时考虑**，并通过硬件级测量获得实际数据，而非依赖理论估计。

### 关键技术细节
1. **测量定义**：
   - **精度 \(P\)**：基准测试正确率（HumanEval 的 pass@1、GSM8K 的精确匹配、MMLU-Pro 的选项正确率）。
   - **时间 \(T\)**：端到端推理的壁钟时间（含 prompt 处理和自回归解码）。
   - **内存 \(M\)**：执行期间的峰值常驻集大小（RSS）。
   - **能耗 \(E\)**：通过 Intel RAPL CPU 封装计数器测量 CPU 能耗。

2. **测量流程（算法 1）**：
   - 固定模型、基准、资源约束和解码配置。
   - 执行一次预热推理并丢弃结果。
   - 对每个实例：等待冷却间隔 → 读取起始能量和时间 → 执行推理（Ollama 后端） → 读取结束能量和时间 → 记录结果。
   - 结束后在测量窗口外进行精度评估，避免干扰。

3. **资源约束设计**：
   - 在桌面级平台上使用 Docker、`cpuset-cpus`、`cpupower` 等工具限制 CPU 频率、核心数和内存上限，模拟五个从紧到松的“资源包络”（E1~E5），分别对应极低端边缘设备到笔记本级设备。

4. **统计分析方法**：
   - 使用配对非参数检验：分类精度用 Cochran’s Q / McNemar 检验；连续指标用 Friedman / Nemenyi 检验。

## 实验设计

### 使用的数据集/场景
三个互补的基准测试，覆盖不同推理负载：
- **HumanEval（代码生成）**：164 个实例，pass@1 正确率。
- **GSM8K（数学推理）**：从 1319 个测试集中随机抽样 200 个实例，精确匹配答案。
- **MMLU-Pro（多任务理解）**：从 14 个类别各抽 20 个实例，共 280 个，零样本设置。

### 对比的模型
六个轻量级量化 LLM，覆盖 1B–7B 参数范围：
- TinyLlama-1.1B、Qwen2.5-1.5B、Gemma-2B、Phi-2（2.7B）、Phi-3-mini（3.8B）、Mistral-7B。
所有模型通过同一 Ollama 后端运行，量化变体均为默认提供。

### 对比方法
主要对比各模型在不同资源包络（E1~E5）下的 PTME 指标，并分析静态代理指标（参数数、FLOPs、加载内存）与实测指标的相关性，以及精度-成本的帕累托前沿。

## 论文的主要结论与发现

1. **RQ1：代理指标能很好预测成本，但无法预测精度**  
   - 参数数、FLOPs、加载内存与实测时间/内存/能耗呈强线性相关（Pearson R ≈ 0.95–1.0），而与精度相关极弱（R < 0.5）。静态描述符只能用于初步筛选，不可替代实测。

2. **RQ2：精度-成本权衡下存在非支配配置，单指标评估会遗漏最佳选择**  
   - 在最紧和最松的包络下，非支配集因任务而异：HumanEval 下为 {TinyLlama, Qwen2.5}，GSM8K 下为 {TinyLlama, Qwen2.5, Phi-3}，MMLU-Pro 下为 {TinyLlama, Qwen2.5, Phi-3, Mistral}。
   - Qwen2.5 在 HumanEval 和 GSM8K 上以极低成本达到接近最佳精度，Phi-3 和 Mistral 在 MMLU-Pro 上精度相近但成本差异巨大。**精度最高不等于部署最佳**。

3. **RQ3：收紧资源包络增加成本但不影响精度，时间放大效应强于能耗，大模型更敏感**  
   - 所有模型精度在 E1–E5 间完全相同（确定性解码）。时间/能耗随资源放松而下降，但时间下降幅度（E1→E5 约 5–6 倍）远大于能耗下降幅度（约 2.7–3.5 倍）。**大模型在资源紧张时成本飙升更严重**，可能抵消其微小精度优势。

4. **实际意义**  
   - 仅凭大小、FLOPs、延迟或精度选模型可能选错。PTME 结合帕累托分析能暴露低物理成本下保持有用精度的候选，尤其适合资源受限场景。

1. **提出首个统一测量四维指标的实验框架（PTME）**，解决了以往研究将精度与效率割裂的问题。
2. **采用硬件级直接测量**（RAPL 能耗、RSS 内存、壁钟时间），结果真实可靠。
3. **系统模拟了五个梯度的资源包络**，从极低端单板机到笔记本级，贴近实际部署场景。
4. **进行了全面的统计分析**（配对非参数检验、相关性、帕累托前沿），结果可信度高。
5. **揭示了反直觉的发现**：代理指标虽能预测成本但误导精度；大模型未必最优（精度提升有限而成本激增）。
6. **提供了可复现的协议和代码**（GitHub），便于后续研究。

## 不足与局限

1. **实验平台限制**：所有实验在桌面机上模拟资源约束，而非真实边缘设备（如 Raspberry Pi、手机）。模拟无法完全复现实际硬件的功耗、热管理和延迟特征。
2. **能耗测量不完整**：仅通过 RAPL 测量 CPU 封装能耗，**排除了 DRAM、存储、外设等系统级能耗**，也未考虑 GPU 加速场景（尽管部分边缘设备已集成 GPU）。
3. **模型与任务覆盖有限**：仅评估 6 个模型（1B–7B）和 3 个任务，结果可能不推广到更大模型或其他领域（如对话、翻译）。
4. **子采样带来的精度损失风险**：GSM8K 和 MMLU-Pro 的随机子采样虽然保证可比性，但可能降低对模型真实性能估计的准确度。
5. **仅适用 CPU 推理**：未考虑 GPU/神经处理单元（NPU）推理下的不同权衡。
6. **固定解码配置**：所有模型使用 greedy decoding（温度=0），未探索不同采样策略对精度和成本的影响。
