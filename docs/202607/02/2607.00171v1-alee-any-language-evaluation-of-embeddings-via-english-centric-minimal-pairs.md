## 摘要
文本嵌入是语义相似度任务的标准方法，但对其评估仍是一个开放挑战。现有基准是静态的，仅覆盖有限的语言集，往往领域特定，易受过度拟合影响，且对低资源语言的代表性不足。为解决这些局限，我们提出ALEE，一个将Sentence Smith（Li等人，2025）扩展到跨语言和段落级别的框架。ALEE使用抽象意义表示（AMR）生成具有受控、细粒度语义变化的英语最小对，并与目标语言的翻译配对。该方法能够对任何拥有英语平行数据的语言中的模型进行定向诊断。我们在多样的嵌入模型集和跨越三个平行数据集的275多种语言上进行了大规模实证研究。在ALEE上，不同语言、文本长度和语言现象下的性能差异显著，暴露了跨语言语义表示中持续存在的差距，这些差距与训练资源中的语言普及程度和子词分词相关。我们在https://github.com/Andrian0s/any-lang-embed-eval发布ALEE。

## Abstract
Text embeddings are standard for semantic similarity tasks, yet their evaluation remains an open challenge. Current benchmarks are static, cover only a limited set of languages, are often domain-specific, susceptible to overfitting, and poorly representative of low-resource languages. To address these limitations, we introduce ALEE, a framework that extends Sentence Smith (Li et al., 2025) to the cross-lingual and paragraph level. ALEE uses Abstract Meaning Representations (AMR) to generate English minimal pairs with controlled, fine-grained semantic shifts, which are paired with translations in target languages. This approach enables targeted diagnostics for models in any language with English parallel data. We conduct a large-scale empirical study across a diverse set of embedding models and 275+ languages spanning three parallel datasets. On ALEE, performance varies substantially across languages, text lengths, and linguistic phenomena, exposing persistent gaps in cross-lingual semantic representation that track language prevalence in training resources and subword tokenization. We release ALEE at https://github.com/Andrian0s/any-lang-embed-eval

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：当前文本嵌入的评估严重依赖静态基准（如MTEB），这些基准存在三个主要局限：
  - **语言覆盖有限**：偏向高资源语言（如英语、德语、法语），对低资源语言代表性极差。
  - **易过拟合**：固定测试集导致模型可能通过记忆或数据泄露获得高分。
  - **粒度粗**：大多使用整体相似度评分，无法区分语义等价与词汇重叠，难以诊断模型对特定语义现象的敏感性。
- **整体意义**：作者旨在构建一个**动态、细粒度、多语言**的嵌入评估框架，能够对任意拥有英语平行数据的语言进行定向诊断，从而揭示跨语言语义表示的系统性缺陷，并推动多语言模型的平衡发展。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- 利用**抽象意义表示（AMR）** 对英语句子进行受控语义编辑，生成与原句仅在单一语义维度（如极性、角色、反义、上下位）上不同的**最小对（foil）**。
- 将英语最小对与目标语言的平行翻译配对，构建三元组 `(en_orig, en_foil, target_orig)`。
- 评估模型是否能正确地将**更高的相似度**分配给 `(en_orig, target_orig)` 而非 `(en_foil, target_orig)`。若模型偏好错误对，说明其对所操控的语义现象不敏感。

### 关键技术细节

1. **AMR操纵类型**（四种语义扰动）：
   - **极性否定（PN）**：通过添加 `:polarity -` 属性反转谓词的真值（如 `approve → not approve`）。
   - **角色交换（RS）**：交换谓词的 `:ARG0`（施事）和 `:ARG1`（受事），改变“谁对谁做了什么”。
   - **反义词替换（AR）**：使用WordNet中的反义词替换一个概念节点（如 `good → bad`）。
   - **上位词替换（HS）**：用上位概念替换原词（如 `penguin → bird`）。

2. **生成与过滤流程**：
   - **解析**：使用AMR解析器将英语源句转化为AMR图。
   - **编辑**：根据四种规则之一修改AMR图。
   - **生成**：使用AMR-to-text模型从修改后的图生成英语扰动词（foil）。
   - **双向蕴含过滤**：使用鲁棒化的NLI模型检查源句与foil之间是否构成语义矛盾——只有当一方蕴含另一方被拒绝时才保留foil，确保语义变化真实有效。

3. **段落级处理**：对于多句段落，采用迭代第一成功策略——逐句尝试编辑，若整个段落的NLI检查不通过则回退并尝试下一句，直到至少一个句子被成功扰动。

4. **评估指标**：**三元组准确率（TACC）** = 模型将更高相似度分配给原始跨语言对而非扰动对的比例。宏观TACC为四种扰动类型的平均。

## 5. 实验主要结论与发现

1. **性能总体排序**：多语言E5-instruct和LaBSE表现最好，但无一模型达到完美（最高TACC约0.9）。解码器模型（Qwen3）尽管参数量大，性能仍落后于最佳编码器，说明参数规模不是主要驱动力。
2. **扰动类型难度**：极性否定（PN）最容易，角色交换（RS）、反义词替换（AR）、上位词替换（HS）难度相近且明显高于PN，说明模型对明显的真值反转更敏感，对结构/词汇深层差异识别不足。
3. **文本长度效应**：段落级文本（仅修改其中一句）比句子级文本难15-16%，说明上下文稀释了语义对比信号。
4. **语言资源关联**：
   - 预训练数据量（CC-100）与性能显著正相关（Spearman ρ≈0.76）。
   - 对于gte模型，微调（对比学习）数据比预训练数据与性能的关联更强。
5. **子词分词**：XLM-R子词碎片化程度越高，性能越低（ρ=-0.78至-0.52），表明分词覆盖不足是低资源语言性能差的关键因素之一。
6. **罗曼什案例**：性能按方言使用人数降序排列（Rumantsch Grischun > Vallader > Sursilvan > ...），且与子词数量完美负相关（ρ=-0.986）。
7. **模型排名迁移**：低资源语言上模型相对排名会显著变化（如gte在罗曼什上排名上升），提示单语言平均分可能掩盖重要细节。

## 6. 优点

- **动态生成**：规避静态基准的过拟合风险，可生成无限的新测试三元组。
- **语言覆盖广**：3个平行数据集涵盖275+语言，包含大量此前无评估资源的低资源语言。
- **细粒度诊断**：四种AMR扰动对应不同语义现象，能精准测试模型的语义理解短板。
- **高效自动化**：整个管线（解析-编辑-生成-NLI过滤）全自动，无需人工标注。
- **段落级扩展**：首次将最小对评估从句子扩展到段落，揭示上下文对语义区分的影响。
- **开源**：代码和数据集已发布，便于复现和扩展。

## 7. 不足与局限

- **英语中心**：所有扰动只在英语侧进行，评估的是目标语言与英语的对齐程度，而非直接评估目标语言内部的语义表示。这天然引入英语偏见。
- **依赖组件质量**：AMR解析器、生成器、NLI过滤器的错误可能引入噪声。虽然人工抽查显示质量高，但仍存在少量格式/句法错误。
- **部分扰动不自然**：角色交换（RS）可能产生不合常理的句子（如“the tide looks at the team”），虽可测试鲁棒性，但也可能引入伪信号（模型可能因“常识”而降低此类句子的相似度，而非语义）。
- **仅测量相对排序**：TACC只能判断模型偏好，不能评估绝对相似度校准。
- **未覆盖所有语义现象**：仅四种扰动，未包含如量词、时态、指代消解等更复杂的语义区别。
- **缺乏重复实验**：未报告多次运行的标准差，统计显著性检验不充分。
- **计算资源未报告**：不利于其他研究者估算复现成本。
