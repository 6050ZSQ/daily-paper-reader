## 摘要
大型推理模型（LRM）通常使用最终答案准确率或标记数量等指标进行评估。然而，这些指标得分相同可能掩盖了根本不同的推理结构。为解决这一局限，我们引入了一个可扩展的逻辑谜题LRM基准测试，以及一个将非结构化轨迹转化为可验证的推理图（包含声明和依赖关系）的流程。这将推理转化为结构化的、可测量的对象，其拓扑结构可进行定量分析。在此基础上，我们定义了一个推理效率指标，用于量化模型逻辑流的集中程度。我们对开源推理模型的分析表明，结构测量能够区分标记计数和准确率所混淆的行为，为诊断失败模式以及比较推理如何随谜题难度扩展提供了实用工具。

## Abstract
Large reasoning models (LRMs) are often evaluated using metrics such as final-answer accuracy or token count. However, identical scores on these metrics can hide fundamentally different reasoning structures. To address this limitation, we introduce a scalable LRM benchmark of logic puzzles and a pipeline that converts unstructured traces into verifiable reasoning graphs of claims and dependencies. This turns reasoning into a structured, measurable object whose topology can be quantitatively analyzed. Building on this, we define a reasoning efficiency metric that quantifies how concentrated the model's logical flow is. Our analysis on open-source reasoning models shows that structural measurements separate behaviors that token count and accuracy conflate, providing a practical tool for diagnosing failure modes and comparing how reasoning scales with puzzle difficulty.

### 1. 核心问题与整体含义

大型推理模型（LRM）的评估通常依赖最终答案准确率或输出标记数（token count）等一维指标。然而，这些指标无法区分根本不同的推理结构：相同的准确率和 token 数可能隐藏集中推理与发散探索的巨大差异。论文旨在解决这一评估局限性，提出一种将非结构化推理轨迹转化为结构化、可量化对象的方法，从而更精细地诊断模型推理行为，并为比较不同模型或同一模型在不同难度下的推理缩放规律提供新工具。

### 2. 方法论

- **核心思想**：将 LRM 的推理过程表示为**可验证的推理图**，其中节点是原子声明（claims），边是演绎依赖关系。通过分析图拓扑结构（如深度、解支撑子图比例）和逻辑流集中度来量化推理质量。
- **关键技术细节**：
  - **推理图提取流程**（图4）：将文本轨迹切分成句子，通过两阶段混合提取（高精度确定性提取 + LLM 补充）获得候选声明，再经 LLM 筛选、去重，得到最终声明集。随后对每个声明提取单一规则应用（前提-结论），构建有向边。所有声明利用可执行谜题环境进行确定性验证（正确/错误）。
  - **推理效率指标 η**（公式(2)）：
    η = (log|V| - H_str(G)) / (log|V| - log|C*|)
    其中 |V| 是图中节点数，|C*| 是解的最小声明集大小，H_str 是结构熵（基于图谱的吸收马尔可夫链计算逻辑流的分散度）。η 值域 [0,1]，越高表示逻辑流越集中在解相关路径上。
- **算法流程**（文字描述）：
  1. 输入 LRM 对谜题实例的完整推理文本。
  2. 分句后用 LLM 和规则提取所有原子声明（保持重复），经筛选得到最终节点集合。
  3. 对每个非自明声明，从推理前缀和已有声明中由 LLM 判断其是否为某规则的应用结果，从而引入边（若前提缺失则标记 C_MISSING）。
  4. 将图转化为吸收马尔可夫链，从源节点均匀初始化，计算每个节点上的逻辑流量 m，进而算 H_str 和 η。

### 6. 主要结论

1. **难度增加准确率陡降**：从 Trivial 到 Human hard，GPT-5 准确率从 83.8% 降至 5.7%，其他模型降至 0% 附近。token 数虽大幅增加，但几乎无助于解决最难实例。
2. **Token 数不是推理质量的代理**：η 与 token 数几乎无关（r=-0.05, p=0.64），说明冗长不等于劣质，且冗长主要体现验证开销（|Vver|/|Vsol| 与 token 数强相关 r=0.53）。
3. **η 能捕获结构差异**：即使准确率饱和，η 仍能区分不同模型的集中程度（图6）。η 与解支撑子图比例正相关（r=0.55），与总图大小负相关（r=-0.33）。
4. **正确性有助于但不够**：声明准确率与 η 中等相关（r=0.33），许多正确但非必要声明会降低效率。
5. **早期错误导致低效**：首次错误出现越晚，η 越高（r=0.28），表明早期错误引发发散探索。
6. **适当冗余有益**：每个唯一声明的重述次数与 η 正相关（r=0.27），可能有助于锚定关键约束。

### 7. 优点

- **方法创新性**：将自由文本推理转化为结构化、可验证的推理图，使推理拓扑可量化，超越传统一维指标。
- **可扩展验证**：使用可执行谜题环境对声明进行确定性验证，确保正确性标签真实可靠（而非仅 LLM 判断）。
- **度量鲁棒性**：η 基于信息论和马尔可夫链，经过多种消融和扰动测试，稳定性良好。
- **领域无关的上层框架**：图构建、马尔可夫链、η 计算与具体谜题无关，仅声明验证需适配域，具有迁移潜力（数学、代码、工具使用）。
- **实验设计严谨**：控制难度、固定实例、多模型对比、温度采样设置一致，并进行了充分消融。

### 8. 不足与局限

- **LLM 依赖的提取**：声明和规则提取使用 LLM（GPT-5.2/5-mini），虽经稳定性分析，但非完全确定，可能存在偏倚（如提取失败或错漏）。
- **域特定声明规则**：每种谜题需手动定义声明类型和规则类型，限制了即插即用性，增加迁移成本。
