## 摘要
运行级通过率高估了免重试覆盖率高达17.8个百分点——且这一差距恰好在中性能系统中最大。我们以编程任务为具体测试平台，研究了大语言模型（LLM）在确定性文本条件生成评估中的准确性与稳定性关系。标准代码生成基准强调单次运行准确性或重复采样下的最终成功，但许多部署场景还需要稳定性：在相同任务描述下多次调用结果的一致性。我们提出了一种重复运行评估协议，包含运行级准确性、免重试覆盖率和每个问题的变异性指标。在一个基于近时性的100道LeetCode风格问题基准上，我们在两种提示模板下评估了来自五个供应商家族的16个模型，每个问题重复运行五次，共产生16,000个评估实例。尽管运行级通过率与完美稳定性率高度相关（r=0.985），但通过率始终超过免重试覆盖率——差距高达17.8个百分点，甚至在性能相近的系统间也逆转了模型排名。提示效应依赖于模型而非普遍有益。这些结果表明，对于确定性文本条件生成任务，重复运行稳定性分析是传统准确性报告的必要补充。

## Abstract
Run-level pass rate overstates retry-free coverage by up to 17.8 percentage points -- and the gap is largest precisely for mid-performing systems. We investigate this accuracy--stability relationship in large language model (LLM) evaluation for deterministic text-conditioned generation, using programming tasks as a concrete testbed. Standard code-generation benchmarks emphasize single-run accuracy or eventual success under repeated sampling, but many deployment settings also require stability: consistent outcomes across repeated invocations under the same task description. We present a repeated-run evaluation protocol with metrics for run-level accuracy, retry-free coverage, and per-problem variability. On a recency-based benchmark of 100 LeetCode-style problems, we evaluate 16 models from five provider families under two prompt templates with five repeated runs per problem, yielding 16,000 evaluation instances. Although run-level pass rate and perfect stability rate are strongly correlated (r=0.985), pass rate consistently exceeds retry-free coverage -- a gap that reaches 17.8 percentage points and reverses model rankings even among closely matched systems. Prompt effects are model-dependent rather than uniformly beneficial. These results suggest that repeated-run stability analysis is a necessary complement to conventional accuracy reporting for deterministic text-conditioned generation tasks.

## 1. 核心问题与整体含义（研究动机与背景）
- **核心问题**：标准代码生成基准（如 pass@k）只关注单次运行正确率或多次采样下的最终成功，但实际部署场景要求模型在多次相同调用下输出一致（即稳定性），而现有评估体系忽视了重复运行间的不确定性。
- **研究动机**：大语言模型在确定性文本条件生成任务（如代码生成、Text-to-SQL）中，即使给定相同输入，输出也可能因随机解码而产生不同结果，导致部分任务需要重试才能成功，这影响了生产环境的可靠性。传统指标（如单次通过率）可能高估模型的真正可靠性。
- **整体含义**：重复运行稳定性分析应作为传统准确性评估的必要补充，尤其对于中等性能的系统，单次通过率与免重试覆盖率之间的差距最大（可达17.8个百分点），且可能导致模型排名反转。

## 2. 方法论：核心思想、关键技术细节、公式
- **核心思想**：提出重复运行评估协议，将“多次采样”从提升性能的手段转变为衡量模型可靠性的视角。引入两个互补指标：
  - **运行级通过率（RLPR）**：所有运行中成功的比例，衡量平均调用成功率。
  - **完美稳定率（PSR）**：在所有重复运行中均成功的任务比例，衡量免重试覆盖率。
  - **平均方差（AV）**：每个问题成功概率的方差平均，衡量任务间的变异性。
- **关键技术细节**：
  - 固定解码参数（温度 T=0.3, top-p=0.9），每个问题重复运行 R=5 次。
  - 使用两种提示模板（DETAILED 和 MINIMAL）进行对照，提示密度不同但输出格式相同。
  - 评估流程：模型输出通过 API 生成后缓存、归一化为统一格式，再提交给确定性测试套件执行，以隔离 API 瞬态故障。
- **公式**（文字说明）：
  - RLPR = 所有运行中正确结果的个数 / (问题数 × 重复次数)
  - PSR = 所有运行都正确的任务数 / 总任务数
  - AV = 平均每个问题内（R/(R-1) × p̂(1-p̂)），其中 p̂ 是该问题的经验通过率

## 3. 实验设计：数据集、Benchmark、对比方法
- **数据集**：从 LeetCode 平台选取最晚发布的 100 道问题（20 Easy, 50 Medium, 30 Hard），覆盖数组、动态规划、字符串、图、模拟等主题。所有问题均有确定性测试套件，只接受 Python 3 解决方案。
- **Benchmark**：该 100 题基准（自定义，非公开标准基准），强调时效性以减少训练数据污染，但未进行污染检测。
- **对比模型**：16 个模型来自 5 个供应商家族（OpenAI、Anthropic、Google、Qwen、DeepSeek），包含旗舰、轻量、推理专用（4 个）等类型。模型列表见表1（GPT-4.1、GPT-4.1-mini、o4-mini、Claude Sonnet 4.5、Claude Haiku 4.5、Gemini 3.1 Pro、Gemini 3 Flash、Gemini 3.1 Flash-Lite、Gemini 2.5 Flash、Gemini 2.5 Flash+Think、QwQ-Plus、Qwen-Plus、Qwen-Max、Qwen-Turbo、DeepSeek-R1、DeepSeek-V3.2）。

## 6. 主要结论与发现
- **核心结果**：运行级通过率（RLPR）始终高于完美稳定率（PSR），差距最高达 17.8 个百分点（Gemini 2.5 Flash 在 DETAILED 提示下）。两者高度相关（r=0.985），但差距非均匀：中等性能模型差距最大，低性能模型（如 Qwen-Turbo）差距极小（2.4 pp），因其结果两极分化。
- **排名反转**：尽管整体相关性高，PSR 和 RLPR 可导致模型排名不同。例如 GPT-4.1 的 RLPR 高于 GPT-4.1-mini（59.6% vs 58.4%），但 PSR 反而更低（47.5% vs 50.0%），说明 RLPR 掩盖了稳定性差异。
- **推理模型无明显优势**：控制 RLPR 后，推理模型的稳定性残差与标准模型无显著差异（置换检验 p=0.97），但个别模型（如 DeepSeek-R1）表现出高于预期的稳定性（残差约 -4.4 pp），需更大样本验证。
- **提示效应异质**：提示模板影响依赖具体模型，无统一最优模板；最大 PSR 差异仅 6 个百分点（o4-mini，但其解码不可控），多数模型差异在 1-3 pp 内，且未达到统计显著性（McNemar p>0.05）。
- **错误模式**：多数失败源于错误算法（Wrong Answer ~58%），而非格式问题；超时和运行时错误在困难问题上增加。
